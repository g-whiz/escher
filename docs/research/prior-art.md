## Abstract

This document surveys existing software for drawing planar symmetry groups and tilings in spherical, Euclidean, and hyperbolic geometry. It gives one entry per tool with the same fields in the same order, a comparison table across all tools, a sorting of the tools into the two rendering families, what Escher can learn from each tool, and the gaps that no existing tool fills. It closes with the conflicts between sources and the claims that remain unverified. Its readers are the people and agents who plan and implement Escher and who need to know what exists, what can be reused under its licence, and where Escher can add something new.

## 1. Scope

This document covers interactive tools, libraries, Rust crates, and computer algebra packages that draw or compute symmetry groups and tilings of the plane, the sphere, and the hyperbolic plane. It also lists the papers and books that these tools name as their design references.

It covers each tool only at the level that a planner needs to compare tools. The document `docs/research/symmhub.md` covers the source code of SymmHub in depth, and Section 4.1 keeps SymmHub at the same level as the other entries. This document states no mathematics that Escher implements. The definitions and algorithms belong to their own subject-matter references.

All facts come from one research pass over public web pages, repositories, and registry metadata, with every source accessed on 2026-11-15. The exception is Dunham's 1986 paper [DUNHAM-1986], which was read in full on 2026-11-16 from a copy that the owner supplied, and which Section 10.2 cites with printed page numbers. Most page text came through a summarizing fetch tool, so a quotation is approximate unless it comes from source code or from API metadata. Licences, dates, file names, and the main capabilities rest on repository and API metadata. The research rated its overall confidence as medium, because several sources could not be read (Section 17).

## 2. Notation and Conventions

These abbreviations and terms are used throughout the document:

- E: The Euclidean plane, written $\mathbb{E}^2$.
- S: The sphere, written $\mathbb{S}^2$.
- H: The hyperbolic plane, written $\mathbb{H}^2$. Three-dimensional hyperbolic space is written $\mathbb{H}^3$.
- orbifold signature: The name of a planar symmetry group in Conway's orbifold notation, such as `*632` or `2223`. This document writes every orbifold signature as an ASCII code span.
- Schlafli symbol: The symbol `{p,q}` of the regular tiling by `p`-gons with `q` meeting at each vertex. This document writes it as a code span.
- wallpaper group: One of the 17 symmetry groups of periodic patterns of the Euclidean plane.
- frieze group: One of the 7 symmetry groups of patterns that repeat along one direction of the Euclidean plane.
- Delaney-Dress symbol: The combinatorial description of a periodic tiling that Tegula and Gavrog use.
- per-pixel inverse mapping: Rendering in which each pixel is mapped back into the fundamental domain of the group and coloured from there. Section 12 lists the tools.
- forward tile generation: Rendering in which copies of a tile or motif are generated by applying group elements outward from a start tile. Section 12 lists the tools.
- GPL: The GNU General Public License, with its version as stated by each source.
- IH type: One of the 93 isohedral tiling types of the Euclidean plane, as Tactile numbers them.

These conventions apply:

- Names that contain accented letters are written in ASCII transliteration, such as Poincare, Schlafli, Wurzburg, Munchen, Fejes Toth, and Etudes, because the prose checker rejects non-ASCII characters.
- This document writes "Poincare disk" for the Poincare disk model. A source title that says "disc" keeps its spelling.
- The proper name `Gray-Scott`, the mode name `Color Symmetry`, and the repository name `colorsym-catalog` appear as code spans, and three URLs appear as code spans in the references, because they contain spellings that the prose checker rejects.
- A citation tag in square brackets, such as [SYMMHUB-REPO], points to an entry in Section 18. A file name in a code span next to a tag is the file inside that source that the fact comes from.
- "Unverified" marks a claim that the research could not confirm from a primary source. "Inferred" marks a claim that the research derived, such as an export format inferred from a class name. "Secondary" marks a claim that rests only on a search summary or a third-party listing. Each claim keeps the status that the research gave it.
- "Not found" means that the research looked for the information and found no statement of it. It does not mean that the feature is absent.

## 3. How to Read an Entry

Each entry in Sections 4 to 9 has these fields, in this order. A field about which the research found nothing is omitted from the entry. A field that the research looked for but could not confirm says "Unverified".

- What it does: The purpose of the tool, in one or two sentences.
- Geometries and groups: The geometries it covers, and the families of symmetry groups or tilings it supports.
- Symmetry input: How the user specifies the symmetry, such as a menu, typed notation, or a configuration file.
- Rendering and models: The rendering family of Section 12, the graphics technology, and the models of the hyperbolic plane it offers.
- Colouring, fills, and animation: Colour symmetry, motif fills, drawing tools, and animation.
- Export: The output formats.
- Language: The implementation language and platform.
- Licence: The licence, and its compatibility with reuse in Escher, which is licensed GPL-3.0-or-later, only where a source states that compatibility. An entry that says nothing about compatibility has not been assessed.
- Latest activity: The latest commit, push, or release that the research found, and whether the tool is maintained.
- Design notes: Papers, talks, or documentation worth reading before Escher implements the same feature.
- Limitations: What the tool does not do, as the sources state it.

## 4. General Symmetry Tools

### 4.1. SymmHub

- What it does: A "Monorepo for symmetry libraries, components, and apps by Vladimir Bulatov and Chaim Goodman-Strauss" [SYMMHUB-REPO]. Its apps are SymPix ("Symmetry from pictures"), SymSim (the `Gray-Scott` and Ginzburg-Landau partial differential equations), and SymChaos (attractors). The apps Orbifold ("General hyperbolic orbifolds"), Groups (subgroup enumeration), and SymDraw ("Vector drawing with symmetry") are under development [SYMMHUB-SITE].
- Geometries and groups: "All 17 planar crystallographic groups", the 7 frieze groups, the spherical polyhedral, dihedral, and cyclic groups, hyperbolic triangle and quadrangle groups, and general hyperbolic orbifolds from orbifold signatures [SYMMHUB-OUTLINE]. SymPix modes include Frieze, Spherical, Wallpaper, Triangle, KLMN, `Color Symmetry`, Orbifold Symmetry, and Scripted Animation [SYMMHUB-SYMPIX].
- Symmetry input: SymPix uses a menu of families. The orbifold app takes a typed orbifold signature, such as `*237`, `2223`, `o2`, and `(12)3x`, with orders of more than one digit in parentheses. It computes the Euler characteristic on entry (`hashOrbifoldString`). Hyperbolic orbifolds expose draggable length and twist parameters, which are Fenchel-Nielsen coordinates [SYMMHUB-NOTATION] [SYMMHUB-SHOWCASE].
- Rendering and models: Per-pixel inverse mapping in WebGL2: "Instead of generating millions of polygonal geometry tiles, SymmHub renders in reverse" [SYMMHUB-OUTLINE]. The GLSL is assembled at run time (`lib/shaders/modules.js`). The edges of the fundamental domain are drawn from a signed distance with one-pixel antialiasing (`lib/shaders/fundDomainShader.glsl.mjs`) [SYMMHUB-REPO]. The models are the disk (the default), log, band, upper half-plane, exp, and loxodromic maps (`lib/shaders/projection.glsl.mjs`), and `projection_v2.glsl.mjs` adds arbitrary complex rational maps. All are conformal maps of the disk, and no Klein or hyperboloid model was found [SYMMHUB-REPO].
- Colouring, fills, and animation: `lib/sublib` computes N-colour symmetry by "Sims-style low-index backtrack over coset tables", validated against 703 files that GAP generated, with presets for the 17 wallpaper groups and the `klm` and `*klm` triangle groups [SYMMHUB-SUBLIB]. A companion catalogue, `colorsym-catalog`, shows no licence [COLOURSYM]. Fills are textures, image arrays, sprites, and the state of a partial differential equation. Animation is scripted animation and reaction-diffusion [SYMMHUB-OUTLINE].
- Export: "canvas WebM video export" through `VideoRecorder`, image recorders, and preset JSON. No SVG or other vector export of a tiling was found [SYMMHUB-OUTLINE].
- Language: JavaScript and GLSL. It needs WebGL2 and an HTTP server [SYMMHUB-REPO].
- Licence: MIT [SYMMHUB-LICENSE]. The research states that MIT is compatible with GPL-3.0, so Escher can reuse the code with attribution.
- Latest activity: Created 2025-02-04, about 684 commits, no GitHub Releases, last push 2026-11-14, with commits by Bulatov on 2026-11-13 and 2026-11-14. Very actively maintained [SYMMHUB-API].
- Design notes: The outline [SYMMHUB-OUTLINE], the orbifold-notation tutorial with "Two Dollars of Symmetry" and the Magic Theorem [SYMMHUB-NOTATION], the sublib README [SYMMHUB-SUBLIB], and Bulatov's talk "Reverse Pixel Mapping" at the Joint Mathematics Meetings (JMM) in 2024 [BULATOV-JMM2024]. The orbifold geometrization in `lib/orbilib/OrbifoldGeometrization.js` follows Deaton's unpublished Princeton senior thesis [DEATON]. The tutorial says "Deaton's construction is a small rewriting system on the notation itself" [SYMMHUB-NOTATION]. Goodman-Strauss describes the method as "chop everything into pairs of pants, and then halve those into right-angled hexagons" [GOODMAN-STRAUSS-GEOM]. `docs/research/symmhub.md` covers the code.
- Limitations: In SymSim, simple symmetrization works for only the 4 reflection groups `*2222`, `*632`, `*333`, and `*442` [BULATOV-JMM2024]. The Orbifold, Groups, and SymDraw apps are unfinished, and `apps/orbifold/bug list.txt` exists [SYMMHUB-REPO]. The research did not run the apps, so the user interface, the model choices, and the export buttons are unverified.

### 4.2. Vladimir Bulatov, Earlier Work

- What it does: Talks, pages, and demonstrations that predate SymmHub, including "Conformal Models of the Hyperbolic Geometry" (JMM, January 2010), "Bending Hyperbolic Kaleidoscopes" (Bridges 2011), "Tilings of the hyperbolic space and their visualization" (2011), and "3D Hyperbolic Tiling and Horosphere Cross Section" (2018) [BULATOV-INDEX].
- Geometries and groups: H, and polyhedra.
- Rendering and models: The 2010 slides catalogue the Poincare disk, upper half-plane, band ($w = \frac{2}{\pi}\tanh^{-1} z$), star, ring, sector, and Julia-set-exterior models. The research rates them as the best catalogue of exotic conformal models, and they name no software [BULATOV-MODELS]. "Dynamical HyperKaleidoscope" is an undated WebGL kaleidoscope in the Poincare disk [BULATOV-DKALEIDO].
- Colouring, fills, and animation: Perfect colourings use the cosets algorithm with low-index subgroups computed in GAP [BULATOV-COLOUR].
- Licence: The polyhedra pages carry a notice that forbids commercial use without written permission (paraphrased) [BULATOV-INDEX]. The Polyhedra Stellation applet was ported to a repository under Apache-2.0 [BULATOV-STELLATION].
- Latest activity: Talks up to 2018. The stellation repository was pushed 2026-09-06 [BULATOV-STELLATION]. SymmHub supersedes this work.
- Design notes: The conformal models slides [BULATOV-MODELS] and the Bridges 2011 paper, of which only the abstract was read [BULATOV-BRIDGES2011].
- Limitations: The stellation port handles polyhedra, not planar tilings. No planar hyperbolic tiling applet by Bulatov from the 2000s was found.

### 4.3. KaleidoTile (Jeff Weeks)

- What it does: "Polyhedron mode creates traditional polyhedra, while Tiling mode smooths your polyhedra into tilings of the sphere, Euclidean plane or hyperbolic plane." "Within each symmetry group, any polyhedron or tiling morphs to any other" [KALEIDOTILE].
- Geometries and groups: S, E, and H tilings, and polyhedra [KALEIDOTILE].
- Symmetry input: Unverified. The in-app guide returned HTTP 404.
- Rendering and models: The file list of the source archive shows SwiftUI and Metal shaders (`KaleidoTileGPUFunctions.metal`), which suggests GPU rendering. Only file names were seen [KALEIDOTILE]. The hyperbolic models are unverified.
- Colouring, fills, and animation: Decoration with photos or colours [KALEIDOTILE].
- Export: Unverified.
- Language: Swift and Metal, judged from file names only [KALEIDOTILE]. It needs iOS 17 and later or macOS 15.4 and later. Older builds exist for macOS on Intel (4.1.5) and Windows (3.10.0) [KALEIDOTILE-APP].
- Licence: "Freeware (GNU General Public License)", with source in `KaleidoTile-Src.zip` [KALEIDOTILE]. Source is distributed as a zip download, and no GitHub repository exists.
- Latest activity: Version 4.4, dated 2025-12-15 [KALEIDOTILE-APP]. Maintained.
- Design notes: Not found.

### 4.4. iOrnament and iOrnament Pro (Richter-Gebert, science-to-touch)

- What it does: iOrnament takes a stroke and "repeats it according to the rules of the 17 crystallographic wallpaper groups" [IORNAMENT-APP]. iOrnament Pro adds "Spherical and hyperbolic symmetries", mandala symmetries, and Escheresque colour symmetries [IORNAMENT-PRO-APP].
- Geometries and groups: iOrnament covers E with the 17 wallpaper groups. iOrnament Pro adds S and H [IORNAMENT-PRO-APP].
- Symmetry input: Unverified.
- Rendering and models: Unverified.
- Colouring, fills, and animation: Colour symmetries in iOrnament Pro [IORNAMENT-PRO-APP].
- Export: Video and time-lapse export in iOrnament Pro [IORNAMENT-PRO-APP].
- Language: iPad apps. iOrnament Pro runs on iPadOS and visionOS [IORNAMENT-PRO-APP].
- Licence: Proprietary [IORNAMENT-PRO-APP].
- Latest activity: iOrnament 2.5.13, 2021-07-17 [IORNAMENT-APP]. iOrnament Pro 2.0.3, 2024-03-24 [IORNAMENT-PRO-APP].
- Design notes: Richter-Gebert, "Etudes in Symmetric Pattern Drawing", Bridges 2025 [RICHTER-GEBERT-2025]. Its text could not be extracted, so the notation and the rendering approach of the apps are unverified.

## 5. Euclidean Pattern Painters

### 5.1. Kali (Jeff Weeks)

- What it does: "Kali can draw patterns in any of the 17 planar (wallpaper) or 7 frieze symmetry groups" [KALI-DEBIAN].
- Geometries and groups: E, with the 17 wallpaper groups and the 7 frieze groups. Windows version 5.3.3 added the frieze names of the International Union of Crystallography and the rosette groups Cn and Dn [KALI-ARCHIVE].
- Symmetry input: One icon button per group, labelled "in Conway notation and the traditional crystallographic notation" [KALI-DEBIAN].
- Rendering and models: Vector line segments [KALI-DEBIAN].
- Export: PostScript printing through `kaliprint` [KALI-DEBIAN].
- Licence: "freeware (fra poco sotto la GNU General Public License)", which means "soon under the GPL" [KALI-ARCHIVE]. Whether the relicensing happened is an open question (Section 17).
- Latest activity: Windows 5.3.3, dated 2008-10-07. Archived and not maintained [KALI-ARCHIVE].

### 5.4. Morenaments (Martin von Gagern)

- What it does: "With Morenaments you can easily paint symmetrical patterns in one of the 17 symmetry groups of the Euclidean space." It shows rotation centres and mirror axes [MORENAMENTS-IMAGINARY].
- Geometries and groups: E, with the 17 wallpaper groups.
- Symmetry input: One button per group, with one class per group from `P1` to `P6mm`. `Controls.createGroupButtons()` builds the buttons, and `GroupButton` calls `main.setGroup` (`src/main/java/de/tum/in/gagern/ornament/Controls.java`, `GroupButton.java`) [MORENAMENTS-REPO].
- Colouring, fills, and animation: A fixed colour palette, the stroke widths `{1, 2, 5, 8, 12}`, undo, and clear (`Controls.java`) [MORENAMENTS-REPO].
- Export: The export package has `BitmapExport` (through `ImageIO.write`), `SvgExport`, `PostScriptExport`, and `OutlineExport`. The formats are inferred from the class names [MORENAMENTS-REPO].
- Language: Java with Gradle [MORENAMENTS-REPO].
- Licence: GPL-2.0 in the repository, GPL 3.0 on the project page. Section 16 records the conflict and its consequence for Escher.
- Latest activity: Last commit 2014-06-26 ("typo fix"), 14 commits. Unmaintained [MORENAMENTS-REPO].
- Design notes: Von Gagern and Richter-Gebert, "Hyperbolization of Euclidean Ornaments", which covers which hyperbolic groups are analogues of the wallpaper groups and a "reverse pixel lookup" [VONGAGERN-2009]. Von Gagern's PhD thesis, *Creating Hyperbolic Ornaments: Algorithmic and Interactive Methods* [VONGAGERN-2014]. Montag, Reinhardt, and Richter-Gebert describe a per-pixel GPU method from the Euclidean plane to the Poincare disk that covers "15 of the 17 groups" [MONTAG-2025].
- Limitations: No released hyperbolic version of Morenaments was found.

## 6. Hyperbolic Tiling Libraries and Viewers

### 6.1. HyperRogue and RogueViz (Eryk Kopczynski, Dorota Celinska-Kopczynska)

- What it does: A game and visualization engine with a tiling engine for many geometries [HYPERROGUE-REPO].
- Geometries and groups: E, S, and H, and many three-dimensional geometries. `archimedean.cpp` reads vertex symbols such as `(3,6,6)` with `^n` and edge pairing in `( )` or `[ ]`, in pure, dual, and bitruncated variations. `arbitrile.cpp` reads "Arbitrary tilings, defined in .tes files". Other sources are `goldberg.cpp`, `fieldpattern.cpp`, `binary-tiling.cpp`, `aperiodic-hat.cpp`, and `honeycombs/` [HYPERROGUE-REPO].
- Symmetry input: `{p,q}`, Archimedean vertex symbols, and `.tes` files, which parse `tile(`, `unittile(`, `conway("...")`, `slider(`, and the geometries `e2`, `h2`, and `s2`. "Most tes files use the Doily notation, e.g. conway("(0 0)(1 2)")". Quotient "orbifolds are obtained by picking a subgroup of the group of isometries of the tiling" [HYPERROGUE-TES]. A catalogue of `.tes` files exists [TES-CATALOGUE]. No input of Coxeter diagrams or orbifold signatures was found.
- Rendering and models: Forward tile generation with OpenGL. The internal model is the hyperboloid. The disk projections are Poincare, Beltrami-Klein, Gans, and inverted Poincare. The plane and other projections are half-plane, hemisphere, band, spiral, polygonal, Joukowsky, a user formula, and cartographic projections [HYPERROGUE-MODELS]. The code is in `models.cpp`, `3d-models.cpp`, and `embeddings.cpp` [HYPERROGUE-REPO].
- Colouring, fills, and animation: Game colouring, field patterns, and animation.
- Export: SVG (`svg::render`, `-svgshot`), PNG (`-pngshot`, `-shotaa`), PNG sequences (`-animrecord`), and MP4 through ffmpeg with libx264 (`-animvideo`), all in `screenshot.cpp` [HYPERROGUE-REPO].
- Language: C++ [HYPERROGUE-REPO].
- Licence: GPL-2.0 ("Released under GNU General Public License, version 2") [HYPERROGUE-REPO].
- Latest activity: Release v13.1p, 2026-11-07, with over 12,600 commits. Actively maintained [HYPERROGUE-RELEASE].
- Design notes: "Generating Tree Structures for Hyperbolic Tessellations", "conceptually similar to Angluin's algorithm" and tested on 149,629 tessellations [KOPCZYNSKI-2021]. "Generating Regular Hyperbolic Honeycombs", of which the authors say "HyperRogue uses the methods described in this paper" [KOPCZYNSKI-2022]. "Conformal Mappings of the Hyperbolic Plane to Arbitrary Shapes", which builds on the band model to avoid loss of precision [KOPCZYNSKI-2019]. "HyperRogue: Playing with Hyperbolic Geometry", Bridges 2017, cited from `CITATION.cff` [HYPERROGUE-REPO].
- Limitations: "The source code is not documented very well." No standalone library exists, so reuse means taking GPL-2.0 game code [HYPERROGUE-REPO].

### 6.2. TilingBot and R3.Core (Roice Nelson)

- What it does: "A twitter bot that creates random 2-dimensional tilings" [TILINGBOT]. R3 is the C# library `R3.Core`, vendored into each of Nelson's repositories. The repository `roice3/R3` returns HTTP 404 [TILINGBOT-TREE].
- Geometries and groups: S, E, and H, with the group `[P,Q]` of a Schlafli symbol `{P,Q}` [TILINGBOT].
- Symmetry input: The Schlafli symbol `{P,Q}`, with options for centring, `ColoringOption` 0 to 4, and geodesic levels (`Format.md`) [TILINGBOT].
- Rendering and models: Per-pixel inverse mapping on the CPU. `Tiler.GenImage` uses `Parallel.For` with 4 by 4 antialiasing, and `ReflectToFundamental` stops after at most 4000 iterations (`TilingBot/Tiler.cs`). A forward breadth-first `ReflectRecursive`, capped by `MaxTiles`, exists in `R3.Core/Geometry/Tiling.cs`. The projections are 9 spherical, 6 Euclidean, and 14 hyperbolic, including Poincare, Klein, hyperboloid, and Schwarz-Christoffel (`Format.md`) [TILINGBOT]. The FAQ says tilings are "generated by repeatedly reflecting an image in mirrors" (`FAQ.md`) [TILINGBOT].
- Colouring, fills, and animation: Five colourings and a picture fill. `Animate.cs` writes 180 PNG frames [TILINGBOT].
- Export: TilingBot writes PNG only. `R3.Core` has the writers `Formats/SVG.cs`, `PovRay.cs`, `STL.cs`, and `VRML.cs` [TILINGBOT-TREE].
- Language: C# [TILINGBOT].
- Licence: MIT [TILINGBOT].
- Latest activity: Last commit 2022-07-03. Dormant [TILINGBOT].
- Design notes: `Geometry/Tiling.cs`, `HyperbolicModels.cs`, and `Math/Mobius.cs` in `R3.Core` [TILINGBOT-TREE].

### 6.3. MagicTile (Roice Nelson)

- What it does: Twisty puzzles on regular `{p,q}` tilings [MAGICTILE].
- Geometries and groups: S, E, and H `{p,q}` tilings.

- Rendering and models: Forward tile generation with fixed-function OpenGL and render-to-texture (`PuzzleRenderer.cs`). The models are Poincare, Klein, upper half-plane, and orthographic, plus surfaces such as Boy's surface [MAGICTILE].
- Language: C# with WinForms and OpenTK. Windows only (inferred) [MAGICTILE].
- Licence: MIT [MAGICTILE].
- Latest activity: Last commit 2026-10-20, with the rolling release `MagicTile_v2.zip`. Active [MAGICTILE].

### 6.5. Malin Christersson's Hyperbolic Tilings

- What it does: "Make Hyperbolic Tilings of Images" tiles an image over a hyperbolic tiling [MALINC-IMAGETILING]. "Interactive Hyperbolic Tiling in the Poincare Disc" draws `{p,q}` with draggable points and rendering styles [MALINC-POINCARETILING]. A set of GeoGebra construction tools, such as HypLine and HypCircle, accompanies them [MALINC-POINCAREDISC].
- Geometries and groups: H `{p,q}` with $(p-2)(q-2) > 4$, where $q$ may be infinite [MALINC-IMAGETILING].
- Symmetry input: Fields for p and q [MALINC-IMAGETILING].
- Rendering and models: Per-pixel inverse mapping, in which the pixel that contains a point B takes the colour of the pixel that contains its preimage A (paraphrased). Poincare disk, with the distortion options none, Klein, or polynomial [MALINC-IMAGETILING].
- Colouring, fills, and animation: Image fill [MALINC-IMAGETILING].
- Export: Download as a raster image, including a large image at 4 times the size and transparent output [MALINC-IMAGETILING].
- Language: JavaScript (inferred).
- Licence: CC BY-NC-SA. The research states that this licence is not compatible with the GPL for code reuse. No source repository exists [MALINC-IMAGETILING].
- Latest activity: The pages are dated 2015-04-19 and 2015-04-13. No maintenance date was found.

### 6.6. Don Hatch's Hyperbolic Tessellations Applet

- What it does: A Java applet for hyperbolic tessellations, last modified on 2004-09-20. The former host hadron.org no longer resolves [HATCH-APPLET].

### 6.7. pywonderland (Zhao Liang)

- What it does: A collection of mathematical visualizations, including uniform tilings, polytopes, and a shader playground [PYWONDERLAND-REPO].
- Geometries and groups: E, S, and H uniform tilings, and polytopes [PYWONDERLAND-REPO].
- Symmetry input: A triangle-group triple plus the active mirrors, such as `Poincare2D((3, 2, inf), (0, 0, 1))`, then `build_geometry(depth, maxcount)` (`example_uniform_tilings.py`). The classes are `Poincare2D`, `UpperHalfPlane`, `Euclidean2D`, and `Spherical2D` (`tiling.py`) [PYWONDERLAND-REPO].
- Rendering and models: Two paths. The SVG path in `src/uniform-tilings/` is forward tile generation in the Poincare disk and the half-plane. The shader `src/shader-playground/glsl/wythoff_hyperbolic/main.frag` is per-pixel inverse mapping that folds the point with `flipTriangleToPoint` in 60 iterations, with the disk, half-plane, band, inverted disk, orthographic, and Klein models [PYWONDERLAND-REPO].
- Colouring, fills, and animation: Face colours per pair of mirrors, and a checkerboard option [PYWONDERLAND-REPO].
- Export: SVG through drawsvg and the `hyperbolic` package of Section 6.9, PNG through Inkscape (`svg2png.py`), and POV-Ray for spherical tilings [PYWONDERLAND-REPO].
- Language: Python and GLSL [PYWONDERLAND-REPO].
- Licence: MIT for the repository. The header of the shader carries CC BY-NC-SA 3.0 and says it "is basically https://www.shadertoy.com/view/wtj3Ry", so the shader's licence differs from the repository's [PYWONDERLAND-REPO] [SHADERTOY-WTJ3RY].
- Latest activity: Last commit 2026-02-03, 4,238 stars. Lightly maintained [PYWONDERLAND-REPO].
- Design notes: The uniform-tilings notes cover the Wythoff construction and exact Coxeter-group arithmetic: "These calculations involve only integer operations, completely avoiding issues with floating-point precision loss". They use shortlex normal forms and an automaton ("SL(W) is a regular language", after Brink and Howlett), minimized with Hopcroft's algorithm. They state that "The algorithm for calculating minimal roots is the biggest performance bottleneck", and they contrast inverse-pixel rendering, which is raster only, with coordinate rendering, which gives vector output [PYWONDERLAND-UNIFORM]. The polytopes notes cover Todd-Coxeter coset enumeration [PYWONDERLAND-POLYTOPES].

### 6.8. hypertiling (University of Wurzburg)

- What it does: "a high-performance Python library for the generation and visualization of regular hyperbolic lattices" [HYPERTILING-PYPI].
- Geometries and groups: H regular tilings. Version 1.4 adds kernels for "arbitrary Schwarzian triangle tessellations" (`CHANGELOG.md`) [HYPERTILING-GITHUB].

- Rendering and models: Forward tile generation through construction kernels: SRS, SRG (the default, which builds adjacency), GR (edge reflections), DUN07, and the optimized DUN07X, which is Dunham's algorithm in hyperboloid coordinates [HYPERTILING-PAPER]. Poincare disk only.
- Colouring, fills, and animation: Colours per cell, and video animation.
- Export: Matplotlib and SVG. Version 1.5 adds an object-oriented `SVGCanvas` with geodesics, circles, and horocycles (`CHANGELOG.md`) [HYPERTILING-GITHUB].
- Language: Python [HYPERTILING-PYPI].
- Licence: MIT ("Every part of hypertiling is available under the MIT license.") [HYPERTILING-PYPI].
- Latest activity: PyPI release 1.5.1 on 2026-03-05 [HYPERTILING-PYPI]. The GitHub repository was pushed 2026-05-25 [HYPERTILING-API]. The repository status conflicts between hosts (Section 16).
- Design notes: The paper in SciPost Physics Codebases, with benchmarks of the construction kernels [HYPERTILING-PAPER].
- Limitations: Refinements "break the discrete rotational symmetry", and neighbour searches become "inaccurate close to the unit circle" [HYPERTILING-PAPER].

### 10.2. Reference Catalogues and Books

- The Tilings Encyclopedia [TILINGS-ENCYCLOPEDIA].
- Conway, Burgiel, and Goodman-Strauss, *The Symmetries of Things*, the reference for orbifold notation, the Magic Theorem, and BCGS symbols [CBG-2008].
- Dunham, "Hyperbolic symmetry", 1986 [DUNHAM-1986]. The hypertiling paper calls it "a very influential work" ([HYPERTILING-PAPER] Section 1.3). Dunham covers the groups $[p,q]$, $[p,q]^+$, and $[p^+,q]$ with the hyperbolic condition $(p-2)(q-2) > 4$ (Section 4, p. 141). He represents isometries by $3 \times 3$ Lorentz matrices on the hyperboloid $x^2 + y^2 - z^2 = -1$ with $z > 0$ (Section 6, p. 147). His replication algorithm handles $[p,q]$ and $[p,q]^+$ with $p > 3$ and $q > 3$ (p. 145, Fig. 9 on p. 146), and its layer count is its only stopping parameter (pp. 146-147). He also defines colour symmetry, with 2-, 3-, and 4-colour examples (pp. 149-152). The DUN07 kernel of hypertiling follows not this paper but "the improved version of Dunham's combinatorial algorithm", from Dunham's 2007 paper "An algorithm to generate repeating hyperbolic patterns" and unpublished notes of about 2007 ([HYPERTILING-PAPER] Section 5.4, p. 28). Dunham's Bridges papers are collected on his home page [DUNHAM-PAPERS].
- Kaplan, *Introductory Tiling Theory for Computer Graphics*, with bibliographic details unverified [KAPLAN-2009].

## 12. Rendering Families

The tools fall into two rendering families. The choice between them decides whether a tool can export vector graphics, because only the forward family produces vector output. pywonderland's notes state this trade-off explicitly [PYWONDERLAND-UNIFORM].

Per-pixel inverse mapping needs no list of tiles, and it suits a fragment shader. Its output is raster only. These tools use it:

- SymmHub [SYMMHUB-OUTLINE].
- TilingBot [TILINGBOT].
- The pywonderland shader [PYWONDERLAND-REPO].
- postmath/hyperbolic-tiling [POSTMATH].
- Malin Christersson's image tiler [MALINC-IMAGETILING].
- The work of von Gagern and Richter-Gebert [VONGAGERN-2009] and of Montag, Reinhardt, and Richter-Gebert [MONTAG-2025].
- Probably KaleidoTile, judged from the file names of its Metal shaders only [KALEIDOTILE].

Forward tile generation produces a list of tiles or strokes that a writer can emit as SVG, PostScript, or EPS. These tools use it:

- HyperRogue [HYPERROGUE-REPO].
- MagicTile [MAGICTILE].
- `R3.Core` `Tiling.cs` [TILINGBOT-TREE].
- The pywonderland SVG path [PYWONDERLAND-REPO].
- hypertiling [HYPERTILING-PAPER].
- Don Hatch's applet [HATCH-APPLET].
- Kali [KALI-DEBIAN].
- Morenaments, which Section 11 marks as unverified [MORENAMENTS-REPO].
- Tactile, which supplies tile geometry and leaves the drawing to the caller [TACTILE-CPP].

| TilingBot (Section 6.2) and postmath (Section 9.1) | Iteration caps in the folding loop, supersampling, state in `f64` on the CPU with only the reduced transform sent to the GPU, and stable colouring through a finite quotient group. |
| Kali, Tess, Morenaments, and Hatch's applet (Sections 5.1, 5.3, 5.4, and 6.6) | Labels in two notations (Kali, Tess), one button per group (Morenaments), and a text symbol in a URL parameter for sharing tilings (Hatch). |
| Tactile (Section 7.1) | Isohedral tile-shape editing as a model for editing Escher-style motifs (Section 14, gap 4). |

## 14. Gaps No Existing Tool Fills

This section is non-normative. It lists the gaps that the research found, as the research states them:

1. No desktop tool and no Rust library accepts an arbitrary orbifold signature for E, S, and H and lets the user paint a motif. SymmHub comes closest, but it runs in the browser and its orbifold app is unfinished (Section 4.1).
2. No tool combines per-pixel GPU rendering for interactive use with true vector export, as SVG or PDF, of hyperbolic patterns. Vector output exists only in the forward-generation libraries, which cover `{p,q}` or triangle groups.
3. No published Rust crate covers wallpaper or frieze groups, orbifold notation, Delaney-Dress symbols, or hyperbolic tilings.
4. No Escher-style tile-shape editor, with edge editing like Tactile's, exists for hyperbolic or spherical groups.
5. Colour symmetry, in the sense of perfect colourings, exists only for wallpaper and triangle groups in SymmHub's sublib, or as one-off GAP work. Nothing covers general hyperbolic orbifolds in a tool for users.
6. No tool offers the full choice of models, such as Poincare, Klein, half-plane, and band, together with pattern painting. HyperRogue has the models but is a game engine, and the painters offer the disk only.
7. Several mature Euclidean painters, namely Kali, Morenaments, Escher Web Sketch, and Hatch's applet, are effectively unmaintained Java or legacy code. That leaves no maintained, free, cross-platform successor except Inkscape's limited Tiled Clones dialog.

## 15. Summary of the Field

This section is non-normative. No existing tool accepts an arbitrary hyperbolic orbifold signature, lets the user draw or edit a motif, colours it, and exports vector output, in a maintained native desktop application with a free licence. Three tools come closest, and each covers only part of this:

- SymmHub takes orbifold signatures and renders per pixel, but it has no SVG export (Section 4.1).
- Tegula covers all three geometries and shows orbifold notation, but it explores tiling types and paints no patterns (Section 7.2).
- HyperRogue has the richest set of hyperbolic models and exports SVG, PNG, and MP4, but its tiling engine is part of a game, and it takes `.tes` files rather than orbifold signatures (Section 6.1).

The Euclidean painters are mature but mostly old or closed (Section 5). The Rust ecosystem has no published crate for the groups and notations that Escher needs (Section 14, gap 3), and its nearest code is the unpublished postmath/hyperbolic-tiling and the dormant `tactile` port (Sections 9.1 and 7.1).
